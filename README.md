## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的规则配置要做文本模式匹配，规则由业务人员自己写，用 JDK 自带正则遇到 `(a+)+b` 这类写法会出现灾难性回溯把 CPU 打满。请从零实现一个正则表达式引擎，**不允许直接调用 java.util.regex 完成匹配**。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 支持字面量、`.`、字符类 `[abc]` 与区间 `[a-z]`、量词 `*` `+` `?`、分组与交替运算；2) 用 Thompson 构造把正则编译成 NFA，并用模拟执行完成匹配，不得使用回溯；3) 支持整串匹配与查找两种模式，查找返回第一个匹配的起止下标；4) 括号不配对、量词位置非法、字符类未闭合必须在编译期报出精确位置与原因；5) 对输入长度与状态数设置上限，超限返回明确错误，测试需证明 `(a+)+b` 这类模式在长输入下能快速返回而不是卡死。`mvn -q verify` 一条命令跑通，README 说明支持范围与已知限制。
